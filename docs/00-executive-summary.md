# WinUse 执行摘要

> **一句话**：做一个**常驻的 Windows 桌面能力服务端** —— 单个二进制 + 本地 HTTP/CLI/MCP 三通道，把 Windows 桌面的"看"和"动"封装成**一套自描述能力**（条数见 07 §0.7 实测表行，不在此写死），让任何 AI 都能接入并接管这台机器。
> **只做 Windows。不是 Agent，不做大脑；只做能力层。**

---

## 1. TL;DR：核心判断

| # | 判断 | 依据 |
|---|---|---|
| 1 | **赛道存在结构性空白**：现有方案要么是 Agent（自己是大脑，不对外开放能力），要么是库（要求你写 Python/C# 同进程调用）。**"Windows 桌面能力服务端"这一层没人占** | `01-market-research.md` |
| 2 | **UIA 必须是默认感知通道，不是可选优化** | Windows Agent Arena 数据：纯像素 OCR+icon 检测 12.5%，加 UIA 无障碍树后 **19.5%（相对 +57%）**【实】 |
| 3 | **Windows 上没有一招通吃的控制能力**，必须做**分层降级栈**，并且**每个动作都要告诉 Agent 自己踩在哪一层** | 能力可行性矩阵 75 条：✅23 / ⚠️35 / ❌17 —— **近一半是"有条件支持"** |
| 4 | **中文 IME 是本项目最可能建立差异化优势的点** | 竞品（Windows-MCP / Windows-Use / 微软 UFO）均诞生于英文语境，其 `type_text` 直接按键模拟，**中文下必然翻车**。Windows-MCP 的 README 甚至写着"Windows 默认语言设置为英文 highly preferred"【实】 |
| 5 | **杀软/EDR 误报是产品化的头号障碍**，不是"发布时顺便做一下"的事 | WinUse 的特征（全局输入注入 + 截屏 + 常驻 + 单文件）与键盘记录器/RAT 高度重合；Akamai 安全研究把 `UIAutomationCore.dll` 被加载到未知进程、`UIA_PIPE_*` 管道**明确列为 UIA 滥用检测指标** |
| 6 | **最大的敌人是"静默失败"** | OSWorld 论文把长任务失败主因归为四条：丢失早期约束 / 漏掉中途信息 / **歧义时猜测而非询问** / **宣称完成前跳过验证**。后两条恰好都能由能力服务端兜底 |

## 2. 产品形态

```
┌─────────────────────────────────────────────────┐
│  单个常驻二进制（用户会话桌面应用，非 Windows Service）  │
│  托盘 UI + HTTP Server + CLI 子命令 + MCP 适配层      │
└───────────────────┬─────────────────────────────┘
                    │  127.0.0.1（默认，永不 0.0.0.0）
        ┌───────────┼───────────┬────────────┐
        ▼           ▼           ▼            ▼
    任意 LLM    CLI / 脚本   MCP 客户端    官方 SDK
                                          (Py/TS)
```

**关键约束**：**必须是用户会话桌面应用，不能是 Windows Service** —— Session 0 隔离会让桌面、输入注入全部失效【实】。

## 3. Windows 操作模式抽取（本次调研的核心工作）

### 3.1 从场景到模式

枚举了 **16 个场景域**（应用生命周期 / 窗口布局 Snap Layouts / 文件资源管理器 / 文本编辑 / 剪贴板 / 浏览器 / 终端 / 设置注册表 / 对话框弹窗 / 输入设备 / 多显示器虚拟桌面 DPI / 会话状态 / 任务栏托盘开始菜单 / 国民级应用 / **中文 IME** / 安装卸载打印验证码等），从中抽出 **5 层抽象**与 **17 个交互模式**。

### 3.2 五层抽象

| 层 | 内容 | 例子 |
|---|---|---|
| **L4 事务治理** | 事务、补偿、审计、确认门、幂等 | 批量重命名失败 → 整体回滚 |
| **L3 宏** | 把高频动作序列打包成一个调用 | `macro.run{form.fill, items:[...]}` —— **这是把典型任务压到 ≤4 次 LLM 往返的唯一手段** |
| **L2 原子动作** | 单个语义动作 | `element.invoke`、`keyboard.type`、`file.write` |
| **L1 定位与同步** | 选择器、等待、作用域契约 | `element.find`、`wait.for`、`scope` |
| **L0 观察** | 读状态、截图、OCR | `element.tree`、`screen.annotate` |

**执行侧的对应分层（降级栈）**：`UIA → MSAA/IAccessible → Win32 消息 → 输入注入 → 像素/OCR`。
**降级方向永远从高往低掉，绝不反向**；每掉一级，`grounding.confidence` 必须下降。

### 3.3 十七个交互模式（精选最关键的 8 个）

| 模式 | 为什么关键 |
|---|---|
| **P1 Locate-Observe-Act-Verify 主循环** | Agent 的基本节拍。缺 Verify 就是静默失败 |
| **P2 选择器优先、坐标兜底** | 坐标点击在混合 DPI 下必然漂移 |
| **P3 作用域/焦点契约** | "点击 (100,200)"在没有上下文时是歧义的 |
| **P5 模态阻断处理** | Windows 上文件对话框 / UAC / 覆盖确认会随时打断主流程 |
| **P10 降级链（含两个特例）** | ① **UIPI 阻断 → 换 UIA 通道**；② **数据层永远优先于 GUI**（读 Excel 用 COM，不要点单元格） |
| **P11 人机接管（挂起 ≠ 失败）** | UAC / 验证码 / 二次验证必须交给人，但**不等于任务失败** |
| **P17 验证必须独立于执行通道** | **不能用产生结果的通道去验证结果**。写文件用 `file.stat`，不用截图 |
| **P6/P7 幂等与补偿** | Windows 上不存在通用真 undo，只能补偿式回滚 |

## 4. 能力范围

**能力集分 15 个域**（条数见 07 §0.7，不写死）：`session` / `system`+`display` / `process`+`window` / `element` / `mouse`+`keyboard`+`text` / `clipboard`+`screen`+`ocr` / `file` / `dialog`+`filedialog` / `browser`+`shell`+`console` / `registry`+`notify` / `macro`+`transaction`+`undo`+`audit` / `wait` / `office` / `plugin`

| 版本 | 条数 | 覆盖 |
|---|---|---|
| **v1（MVP）** | **见 07 §0.7.12** | PRD 全部 P0 + 少量 P1 主干 |
| v1.5 | 33 | 事务、事件订阅、CDP、终端、Snap、虚拟桌面查询、宏录制 |
| v2 | 21 | 托盘 / Toast / 虚拟桌面切换 / 模板匹配 / 回收站 / console |

**风险分布**：`read` 37% / `low` 30% / `high` 17% / `destructive` 4%（另有 3 条按内容条件升级为 destructive）。

自绘 UI 元素级控制（微信/企微/钉钉/QQ）· UAC 弹窗 · 锁屏/屏保/休眠下任何操作 · RDP 断开后继续 · 最小化窗口截图 · 非当前虚拟桌面窗口截图 · DRM/防截屏内容 · 虚拟桌面切换 · 通知中心历史 · 系统托盘图标点击 · 游戏内 UI · mstsc 内部窗口 · **以 Windows Service 运行** · 模拟按键序列输入中文 · 普通权限操作 High IL 进程 · 绕过网银/密码控件 · 无交互静默启动屏幕捕获

## 5. Agent 友好的七个设计（这是本项目的产品内核）

| # | 设计 | 解决什么 |
|---|---|---|
| **1** | **`grounding` 强制返回**：`{layer, confidence, degraded, fallbackReason, attempts}` | Agent 能否可靠工作，取决于它**知不知道自己踩在哪一层**。忽略 grounding = 闭眼开车 |
| **2** | **错误码自带可执行恢复指引**：`recovery: retry\|degrade\|escalate\|abort\|wait_resume` + `hint` + `suggested_next` | Agent 友好性取决于**错误是否可执行**。不是"失败了"，而是"下一步该干什么" |
| **3** | **`NEEDS_HUMAN` = 挂起，不是失败**，带 `resume_token` 可恢复 | 直接对冲 OSWorld 列出的两条失败主因（歧义时猜测、跳过验证） |
| **4** | **分层暴露**：`core` / `extended` / `advanced` 三档（条数见 07 §0.7.13 的 `tier` 列） | v1 全部 tools 全塞给 LLM 会**显著降低工具选择准确率**并撑爆上下文 |
| **5** | **SoM 标注（`screen.annotate`）**：返回"编号 → 元素"映射，Agent 说"点 7 号"而不是"点 (842,311)" | 既是省 token，也是**从像素层爬回语义层的桥梁** |
| **6** | **默认不返回图像**、diff 增量、`max_tokens` 预算 | 单次观察增量 ≤800 token |
| **7** | **一键导出 OpenAI / Anthropic / MCP 三种 tools 格式**，且把 `风险/幂等/通道` 追加进 description | 零转换接入；**宁可多几十个 token，也不能让 Agent 在不知风险的情况下调用 `shell.exec`** |

## 6. 关键技术决策

| 项 | 结论 | 理由 |
|---|---|---|
| **语言** | **C# / .NET 8+，self-contained 单文件** | 三大核心技术资产（UIA=COM、`Windows.Graphics.Capture`=WinRT、`Windows.Media.Ocr`=WinRT）全是 COM/WinRT，C# 是唯一能同时低成本吃下的选项 |
| **权限** | **默认 Medium IL** | 管理员常驻会显著放大 SmartScreen/杀软压力。**代价已明确**：管不了以管理员运行的进程 |
| **坐标系** | **物理像素 + 虚拟屏幕坐标（VSC）** + 强制 Per-Monitor DPI Awareness v2 | 混合 DPI 下存在三套坐标系，同一窗口可返回 500×500 / 1000×1000 / 1500×1500。VSC 与截图、`GetCursorPos`、UIA 全同源 |
| **中文输入** | `ValuePattern.SetValue` → `KEYEVENTF_UNICODE` → 剪贴板粘贴，**每层都读回校验**；**禁止**模拟拼音按键序列 | `SendInput` 不经过 IME 组字；按键序列需知道 IME 状态与编码方案，无解 |
| **视觉模型** | **v1 不内置任何视觉定位模型** | OmniParser 的 icon_detect 权重是 **AGPL**，内置触发传染性。v1 走 `Windows.Media.Ocr`；视觉定位为外置插件、**我们不分发的二进制** |
| **传输** | **JSON-RPC 2.0 over HTTP（单端点）+ SSE + CLI 镜像** | 能力 ID 与 method 一对一、零映射（条数见 07 §0.7）；导出 LLM tools 是零转换；CLI 与 HTTP 走同一 Dispatcher，行为完全一致 |
| **MCP 定位** | **MCP 是入口，不是本体** | stdio 是单客户端模型。若做成"纯粹一个 MCP server"，会退化成又一个 Windows-MCP 竞品，**丢掉"常驻能力服务端"这个第一差异化** |
| **支持矩阵** | Win11 22H2+ 为一等公民；Win10 22H2 "尽力兼容" | Win10/Win11 的 UIA 树存在真实差异（如"未保存更改"对话框：Win10 子对话框、Win11 窗口内嵌），用双形态选择器吸收 |
| **Office** | v1 做 Excel/Word COM，**不做通用 COM 逃逸口** | 通用口等于把整个 COM 攻击面暴露给 LLM，审计与风险分级都做不了 |

## 7. 硬边界：不做什么

| 不做 | 原因 |
|---|---|
| 不自动化 UAC / 锁屏 / 凭据 / 验证码 | Windows 刻意设计不可达；**且我们不应绕过** |
| 不做视觉模型 / 不做 Agent 编排 / 不做跨平台 / 不做云端 | 保持"能力服务端"这一定位 |
| 不做 RPA 可视化编排器 | 目标用户是 AI，不是业务人员 |
| 不面向游戏作弊 | — |
| **不隐藏失败** | 硬约束 C8。任何失败必须显式返回，**禁止把 halt 说成 success** |
| 安全默认值**不可配置关闭** | R3/R4 确认门、`registry.*` 默认禁用、不可自动化清单、全量审计 —— 这些不能做成可选关闭项 |

## 8. 风险（按严重度）

| 级别 | 风险 | 缓解 |
|---|---|---|
| 🔴 **最高** | **杀软/EDR 误报导致应用无法启动** | EV/OV 签名（T-12 周启动）；向 Defender/360/火绒/腾讯提交白名单（T-8 周起）；编码约束清单禁止注入类 API；**开源透明是最强背书** |
| 🔴 | 自绘 UI（微信/企微/钉钉）元素级控制不可行 | 诚实列入不支持清单；PIXEL + SoM 降级；Bench 中标预期降级路径 |
| 🟠 | 中文 IME 输入不可靠（**差异化失效**） | 四层策略链 + 强制读回校验；PoC 覆盖 Top-10 应用 × 3 种输入法 |
| 🟠 | 混合 DPI 坐标漂移（**不报错，只是错**） | 强制回读校验；≤2px/≤5px 分级判定；PoC 校准 |
| 🟠 | Bench 成功率目标 ≥70% 可能显著高于 SOTA | 参照：UFO²(o1) WAA 30.5%、OSWorld-W 32.7%。**第一轮跑完据实调整目标值，而不是调整题目** |
| 🟡 | 动态风险升级是启发式，**存在漏判** | 如实写入文档，不给硬保证；R3/R4 确认门兜底 |

## 10. 诚实性说明（这次调研的自我约束）

本文档及全部子文档沿用三级可信度标注：**【实】已核实（附来源）/【推】推断 /【PoC】待实测**。

并额外做了一次专项审计，把**未经验证的 Windows 物理事实**与**产品期望值**从验收标准里挑出来，登记为 **28 条假设**（`11-assumptions-register.md`）：

- **1 类（12 条）**：断言了尚未实测的 Windows 行为 —— 其中 **5 条阻塞**。典型如"UIA 能绕过 UIPI"，已修订相关 AC。
- **2 类（11 条）**：把期望值写成事实 —— 如"跨屏点击 ≤2px"（PM 自评"拍脑袋"）、Bench 的 `Δ≥30pp`、成功率 `≥70%`。
- **3 类（5 条）**：依赖互相矛盾或无法复核的二手数据 —— 如 UFO² 的 WAA 成绩存在 30.5% 与 89% 两个版本（取 30.5%）；OSWorld 榜单中若干模型名超出先验知识（已标 ❓，不将结论建立其上）。

**已知做得比我们好的竞品**（不自欺）：UI-TARS / Fara-7B 的视觉 grounding（ScreenSpot-Pro 40–58%）远强于我们自研；Agent-S 的双重记忆；OpenAdapt 的"效果契约 + 独立通道核验 + 绝不把 halt 说成 success"；Windows-MCP(.NET) 的多显示器 DPI 处理与自动快照 diff（实测 84–96% token 节省）。**这些应直接采纳，而不是重新发明。**
