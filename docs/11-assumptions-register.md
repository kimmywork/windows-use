# WinUse 待验证依赖与假设登记

> **为什么有这份文档**：本项目的需求与验收标准里，混着三类内容——已核实的 Windows 行为、**尚未实测的推断**、以及**产品期望值**。三者写在一起会让排期建立在流沙上。
> 本文档把它们分开登记，**每条给出建议改写与对应的 PoC 编号**。
>
> **建立时间**：2026-09-22　｜　**触发原因**：`05-architecture.md` ADR-002 发现 PRD P0-6 AC③ 断言了未验证的物理事实。
> **维护规则**：每当有 PoC 出结果，必须回来更新对应条目的状态（✅证实 / ❌推翻 / ⚠️部分成立），并回写被影响的文档。
>
> **版本历史**：
> - 2026-09-22 建立（28 条）
> - 2026-09-22 PoC 第一轮后更新（32 条，5 条结案）—— 见 §7
> - **2026-09-22 晚些时候：本文件曾被误覆盖，此为逐字恢复版**（原始 28 条逐字保留 + PoC 轮更新）。恢复依据：team-lead 上下文中的原稿全文。若发现与 `00` / `03` §11 / `09` 的引用不一致，以本版为准并回报。

> **2026-09-22 PoC 第一轮后**：新增 4 条此前**根本没登记**的隐含假设（A-13~A-16），其中 **3 条被实测推翻**。这说明一件事：真正危险的不是登记在册的假设，而是那些"没人意识到它是假设"的隐含前提。

**当前剩余 5 条 🔴 阻塞项**：
1. `A-02` 副屏负坐标 / 异构 DPI —— 需多显示器环境

5. `B-09` 成功率目标值重估 —— 需 Bench 第一轮跑完

**共同点：5 条全部卡在"本机环境不具备条件"，而不是卡在设计**。这意味着继续在本机空转无法清零它们，必须换环境或先做 M1 内核。

## 7. PoC 第一轮结论摘要（2026-09-22）

> 非侵入式只读 PoC，工程在 `poc/WinUse.PoC/`，原始数据在 `poc/poc-results.json`（51KB），日志 `poc/poc-run.log`。
> 采集环境：**Windows 11 Build 26200 / 单显示器 1920×1080 @125%（120 DPI）/ 探测进程 IL=Medium 未提权 / 12 个可见顶层窗口**。

| 编号 | 结论 | 影响的假设 | 状态 |
|---|---|---|---|
| **C1** | UIPI 阻断已证实：管理员窗口 UIA 完全不可见（0/1），普通窗口 100% 可见 | A-01 | ✅ 证实，结案 |
| **C2** | PMv2 声明是硬要求：未声明时 `GetDpiForSystem` 谎报 96（真实 120），12/12 窗口坐标全错 | A-02 子项 | ✅ 证实 |
| **C3** | UIA `BoundingRectangle` == `GetWindowRect`（物理像素）；DWM 视觉边界比它们小 8~9px | A-16（推翻原推测）+ 新缺口 | ✅ 结案 + 新约束 |
| **C4** | `ImmGetContext` 在 8/8 真实窗口返回 NULL，IME 状态无法预判 | A-14 | ❌ 推翻，结案 |
| **C5** | `IsWindowVisible`=TRUE 的 12 个窗口中 3 个是 cloaked 幽灵 | A-13 | ❌ 推翻，结案 |
| **C6** | UIA 顶层列表含系统窗口与隐藏事件窗口（4/12 在 Win32 侧不存在）；顶层 `FrameworkId` 一律 "Win32" | A-13 | ❌ 推翻，结案 |
| **C7** | 290 个进程中 135 个（46.6%）查不到 IL | A-15 | ⚠️ 部分成立，结案 |
| **C8** | 12 窗口 UIA 顶层枚举 551ms，25s 超时未触发；但无国产 IM、无无响应进程，样本不足 | A-03 / A-04 | ⚠️ 轻负载未复现 |

**诚实说明**：本轮**没有**验证的（不要误读为已解决）——多显示器异构 DPI、VSC 负坐标原点、国产 IM 覆盖率、高负载 UIA 挂死、对话框树形态（采样时无 `#32770` 对话框打开）、`SetCursorPos`/`SendInput` 实际行为（属侵入式操作，本轮刻意未做，避免干扰用户）。
